- **Summary:** Authored `docs/roadmap/phase07-roadmap.md` in PR #89 (`42cb0a3`, `2026-11-03`) breaking Phase 7 (Depth) into ten executable steps (`Step 1` through `Step 10`) with 65 static checks and the 42-row V1–V10 post-implementation verification matrix (`107` total checks in `--post`), and amended `docs/roadmap/ROADMAP.md` (§2/§3 outbound Nominatim search, ntfy push, and nowCOAST WMS boundaries, §5 operational health/alarm rows, and Phase 7).

  - Forward geocoding via Nominatim's `/search` endpoint (`format=jsonv2&addressdetails=1&limit=5`) with an in-memory-only LRU cache (never persisted to SQLite so unpicked candidate coordinates never touch disk) and coordinate-redacted query parameter `q` (#71), paired with optional `NwsCoverage.county_zone` for US marine points (`#87`).

  - Comment-preserving `weatherbot.toml` editing via `tomlkit` (`src/weatherbot/services/settings_file.py`) restricted to 12 allowlisted `(table, key)` pairs with `expected_sha256` optimistic concurrency, paired with `RetentionService` / `RetentionWorker` (Alembic revision `0010` foreign-key indexes, keep-list protection for the latest snapshot and assessment per location, pre-prune SQLite backup before the first delete batch since `serve` startup, and `weatherbot prune`).
  - Map depth (`GET /api/map/depth`, `GET /api/map/wind-probabilities`, `GET /api/map/advisories`), nowCOAST radar and satellite WMS overlays (`https://nowcoast.noaa.gov`), accessible hand-built SVG charts (`frontend/src/charts/`, zero new npm packages), the `/replay` historical storm scrubber page (`GET /api/replay/{atcf_id}/timeline` and `/assessment`), and self-contained offline HTML threat reports (`GET /api/report` and `weatherbot report` built over `briefing_context`).

Kept `parse_point` strict on the `/points` contract while making `county` optional (`OPTIONAL_POINT_FIELDS`) and logging the specific validation field name on `SourceSchemaError` (without coordinates or URLs). Fixed in PR #91.
  - **CheckConstraint `nws_coverage_whole` in SQLite:** Kept `LocationRow`'s table check constraint requiring `forecast_zone` and `cwa` together while allowing `county_zone` to be `NULL`, avoiding any `batch_alter_table` migration on `locations` (whose cascade would wipe foreign-key child tables in SQLite). Fixed in PR #91.
- **Disposition:** Merged in PR #91 (`7380f30`, `2026-11-04`), closing GitHub issues #71 and #87.

- **Findings & judgement calls:**
  - **Order-dependent `current_goldens` recursion under `pytest -n auto` (`tests/engine/test_golden_replays.py`):** When `xdist` scheduled `test_golden_check_is_read_only_and_requires_all_approvals` on a worker before any `test_every_engine_timeline_equals_its_golden` item had warmed `@cache def current_goldens()`, `monkeypatch.setattr(build_goldens, "candidates", current_goldens)` caused `current_goldens()` to call the patched `build_goldens.candidates` (`RecursionError`). Skipping `Geometry` instances in `_provenances()`, computing `tuple(_provenances(self))` once in `Snapshot._consistent`, and caching parsed `(ConeGeometry, ArchiveStorm)` and `WindProbabilityProduct` in `ReplayCorpus` after SHA-256 verification cut `ReplayService.timeline("AL112017", ...)` from `11.45 s` to `2.94 s` and brought all 8 CLI subprocess replays in `scripts/verify_phase03.py`'s `replay_budget()` (`V6.5`) down to `3.2 s–6.0 s` (well under the `10.0 s` ceiling).
  - **Nested verifier pagination, retry, and pre-PR branch fallback (`scripts/verify_phase01.py`–`scripts/verify_phase06.py`, `scripts/eval_ai.py`):** Updated `operator_settled_briefing()` in `scripts/verify_phase06.py` to query `/api/ai/calls?limit=100` (so background `ChangeSummarizer` rows recorded since Phase 6 do not push the settled briefing row past the default `limit=20` window), aligned `_client()` in `scripts/eval_ai.py` with `default_client()` (`max_retries=2` for transient HTTP 429/5xx/529 retries), and ensured `scripts/verify_phase01.py`–`scripts/verify_phase06.py` share the pre-PR branch fallback (`git("rev-parse", "HEAD") == git("rev-parse", "main")`) and `-n auto`.

## Source-drift observations

- **Central Pacific arrival-time KMZ antimeridian coordinates (`CP042026` Pena, `2026-11-10`):** NHC's `nhc-toa-34-er` and `nhc-toa-34-ml` KMZ feeds for storms crossing `180°W` emit KML `<coordinates>` with longitudes unwrapped into `[-360, -180)` or `(180, 360]`. `src/weatherbot/sources/nhc_arrival_times.py` now normalizes those longitudes into `[-180, 180]` before constructing the WGS 84 `Geometry` (PR #104; documented in `docs/DATA_SOURCES.md`).
- **NWS `/points` marine points without `county` and `/zones` list-typed `cwa` (`2026-11-04`):** US offshore points return `county: null` with a valid `forecastZone`, while `/zones/{type}/{id}` can return `"cwa": ["KEY", "MFL"]`. `src/weatherbot/sources/nws.py` treats `county` as optional (`OPTIONAL_POINT_FIELDS = frozenset({"county"})`) and `NwsCoverage.county_zone` is `str | None = None` (PR #91, closing #87).
- **Peak Storm Surge (`PeakStormSurge` Layer 4 vs. `StormSurgeRisk`):** No active storm during Phase 7 carried live `PeakStormSurge` polygons/lines on NHC's GIS service; Step 5 tested the full pipeline with a deterministic synthetic fixture (`scripts/synthetic_surge.py`, `provenance.source_id = "synthetic-peak-storm-surge"`), documented that `StormSurgeRisk` (`P-Surge` raster catalog) is not drawn, and tracked live `PeakStormSurge` capture in GitHub issue #95.
